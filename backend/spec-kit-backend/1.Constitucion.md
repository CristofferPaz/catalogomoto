# Constitución técnica del backend

## Objetivo

Construir una API REST para autenticar administradores y gestionar el catálogo de motos almacenado en SQL Server.

## Decisiones técnicas

- TypeScript sobre Node.js Runtime.
- Hono como framework HTTP y exportación `default` desde `src/index.ts` para Vercel.
- `@hono/node-server` para desarrollo local (`npm run dev` o `vc dev`).
- PostgreSQL mediante `pg`, usando un pool singleton reutilizable en Functions y `DATABASE_URL` como cadena de conexión.
- JWT firmado con `jsonwebtoken`, guardado en cookie `HttpOnly`, `SameSite=Lax` y `Secure` en producción.
- bcrypt con ocho saltos. El seed (`src/database/seed-admin.ts`) genera el hash del administrador.
- Zod para variables de entorno, autenticación, motos y filtros.

## Arquitectura

La aplicación está organizada en tres capas:

1. **HTTP:** `routes`, `controllers`, `middlewares` y `schemas` reciben solicitudes, validan datos y forman respuestas.
2. **Aplicación:** `services` contiene autenticación y reglas de negocio.
3. **Persistencia:** `repositories` y `database` ejecutan consultas SQL Server exclusivamente parametrizadas.

## Endpoints

| Método | Ruta | Acceso | Función |
|---|---|---|---|
| GET | `/` | Público | Estado de la API |
| POST | `/api/auth/login` | Público | Compara bcrypt, genera JWT y establece cookie |
| POST | `/api/auth/logout` | Público | Elimina la cookie JWT |
| GET | `/api/motos` | Público | Lista y filtra por modelo, marca, categoría, cilindrada, precio y stock |
| POST | `/api/motos` | Administrador | Registra una moto |
| PUT | `/api/motos/:identificador` | Administrador | Actualiza parcialmente una moto |

Las respuestas de listado tienen la forma `{ data, total, filtros }`. Los errores tienen `{ error: { codigo, mensaje, detalles } }`; los errores internos no exponen información sensible.

## Variables de entorno

Consultar `.env.example`. Son obligatorias la conexión (`DB_*`) y una clave JWT de al menos 32 caracteres. Nunca se versiona `.env`.

## Fases

1. Constitución y configuración de TypeScript, Hono y Vercel.
2. Pool singleton y repositorios parametrizados para SQL Server.
3. Validación con Zod y middleware de errores.
4. Login, logout, JWT, cookies y seed bcrypt.
5. Alta, actualización, listado y filtros de motos.
6. Pruebas de autenticación, validación, CRUD, filtros y conexión.
7. Configuración de variables, CORS/HTTPS y despliegue en Vercel.

## Dependencias

Producción: `hono`, `@hono/node-server`, `@hono/zod-validator`, `zod`, `jsonwebtoken`, `bcrypt`, `pg` y `dotenv`.

Desarrollo: TypeScript, `tsx`, Vitest, ESLint, Prettier y tipos de Node, bcrypt y jsonwebtoken.
